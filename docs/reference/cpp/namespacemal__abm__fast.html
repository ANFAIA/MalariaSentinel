Detailed Description

SPDX-License-Identifier: MIT wire.hpp — single shared header for the C++ ABM engine (M-perf / mal-abm-fast).

This is the canonical "data contract" header. Every module in mal-abm-fast includes wire.hpp to pick up:

  • the model-constant accessors (EIP thresholds, dispersal kernel, birth rate, the no-data sentinel — all read from model_constants.yaml), the state-band names and the contract / generator version strings
  • the shared value types (AOI, HabitatPatch, PatchState, DensityGrid, SuitabilityGrid)

Historical note: bit-for-bit parity with the retired Python Mesa-Geo engine was the constraining invariant until proxy_habitat_v1 removed the Python engine (plan docs/plans/in-process/redesign/01-retirada-*.md §9). Parity tests compare against the historical baseline outputs.

The wire.hpp header is header-only. The AOI::cells_per_side() method is defined in aoi.hpp (separately compiled into the library, although header-only is also viable).

SPDX-License-Identifier: MIT output_contract.hpp — 2-band state COG writer + sidecar JSON writer.

The state COG is a 2-band GeoTIFF (band 1 = adult_patch_count, band 2 = adult_cell_count), tiled, deflate-compressed, 128x128 blocks, with nodata = NODATA_SENTINEL(). The band names are the single source of truth in wire.hpp (STATE_BAND_NAMES); the values are raw per-cell adult counts — no capacity normalisation. The sidecar JSON is a small metadata file written next to the .tif (e.g. ghana_regional_2024_06_seed0001.json for the COG ghana_regional_2024_06_seed0001.tif).

The sidecar is the F1.e parity test's primary input — it lists contract_version, generator_version, band_names, nodata, etc. (the k_max key was retired with contract 4.0). Two engines producing the same state COG bytes for the same inputs must also produce byte-equal sidecars.

SPDX-License-Identifier: MIT habitat_availability.hpp — the single number (0..1) that determines whether mosquitoes CAN breed in a cell right now. Contract v3.0.

habitat_potential : static per-cell amplitude, six habitat types update_z_step : one-day pluvial recursion (rain-driven) species_accuracy : daily accuracy, affinity × potential × availability k_habitat : absolute per-cell capacity in individual-equivalents

Legacy foreword (plan 01 §7): what was removed is what didn't belong — the pool water balance in mm and its constants, the TWI gate, the urban mm floor, and the urban capacity clamp K_eff. Rain only enters the pluvial reservoir as a forcing; total water is not reconstructed.

The urban persistent supply premise (user-fixed): leaks, seepage, drainage and human water storage support small dry-season breeding supply, represented by urban.beta_urban × lc_built (a proxy, not a measurement, not a forced depth).

SPDX-License-Identifier: MIT habitat_engine.hpp — candidate habitat patches reader (gpkg via OGR).

Contract v3.0: a single-layer OGR Point datasource; the loader reads

  • optional hab_type (string; accepted without filtering)
  • optional habitat_potential (float, [0,1]; default = full potential)
  • optional dynamics (int; 0 = persistent, 1 = pluvial)
  • optional row, col (int32; pre-computed cell index)
  • the Point geometry (lon, lat) Features below the habitat.candidate_min_engine floor are dropped.

SPDX-License-Identifier: MIT coordinator.hpp — Mesa-Geo half of the C++ ABM (the spatial layer).

Contract v3.0 (proxy_habitat_v1): the coordinator owns

  • the AOI (cell geometry + transform)
  • the ClimateEngine (env NC reader: daily rainfall + air temperature, five static habitat planes)
  • the HabitatEngine (candidate-patch gpkg reader)
  • a Prng (the per-rollout sub-stream; derived from --seed)
  • the shared temporal responses (one pluvial state z per cell, warm-up-integrated causally over the env-NC bands before the simulation start) and the per-cell species-neutral daily capacity K[i, t] = K_ref * cell_area_km2 * S[i, t]

There is NO per-patch water-balance solver, NO TWI gate, NO urban mm-floor and NO ndvi channel (plan docs/plans/in-process/redesign/ 01-retirada-hidrologia-dem-escorrentia.md §6-§8).

Per-day contract (matching the retired Python engine's surface):

  1. coordinator.update_habitat_day() — z/S/K update from rain
  2. patch_states = coordinator.to_dataframe()
  3. submodel.advance_day(aoi, patch_states)
  4. density/suitability aggregation
  5. coordinator.write_state_cog(...)

SPDX-License-Identifier: MIT config.hpp — single model-constants source for the C++ engine (plan constants-yaml §4). mal-core/config/model_constants.yaml is the ONLY source of shared py⇄C++ parameters. The loader:

  • parses a PLAIN YAML SUBSET with a hand-written micro-parser (no yaml-cpp dependency; see config.cc SupportedSubsetData rules);
  • fails LOUDLY: missing keys are reported as a COMPLETE list, unknown keys (typos) are an error, wrong types are an error, duplicate keys inside the file are an error;
  • embeds NO default for any model key — the YAML is the source;
  • pre-transforms species weight rows by habitat NAME → ZoneId once at load time (the day-loop consumes a plain std::array);
  • derives num_persistent from habitat_types.dynamics (no "the first three are persistent" positional rule).

singleton: load_config() reads once per process (env MAL_MODEL_CONSTANTS overrides the default search).

Inline method definitions

AOI::cells_per_side — number of cells along the east-west axis (WIDTH). The full derivation lives here (rather than in aoi.hpp) so that every translation unit pulling in wire.hpp sees the inline definition and the linker does not have to find a separate .cpp definition. aoi.hpp contains the related free function cells_per_side_h (H dimension).

Parity with the Python reference (mal_commonlib.aoi.AOI.cells_per_side): m_per_deg_lat = π · R / 180 from geodesy.* (WGS84 mean Earth radius) width_m = (east - west) * m_per_deg_lat * cos(centroid_lat_rad) cells_per_side = ceil(width_m / resolution_m) (NOT lround — see parity note)

F1.b parity note: Python's mal_commonlib.aoi.AOI.cells_per_side uses math.ceil (not round); we use std::ceil to match. For the Ghana regional AOI both formulas agree; for AOIs near a cell boundary the rounding mode diverges.

◆ STATE_BAND_DENSITY

int mal_abm_fast::STATE_BAND_DENSITY = 1
inlineconstexpr

Adult daily mortality: thermo-dependent survival with a basal cap (values in adults.*; formula in mosquito_submodel.cpp). Temperature NaN policy (2026-10-13): the legacy per-lookup temperature fallback constant was removed. Out-of-coverage / sea-mask NaN pixels in the env NC water_temp_c channel are imputed at load time by neighbor-mean wavefront fill (climate.cpp impute_temp_nans) — each imputed cell inherits the same day's spatial temperature field, so it tracks the seasonal cycle instead of pinning a fixed value year-round (the fixed fallback put out-of-place values on coastal/edge cells in hot and cold seasons). temp_at() clamps off-grid (row, col) to the border cell; the only remaining fallback is a documented degenerate-engine guard for an all-NaN slice or an unloaded engine. Larva desiccation: grace + daily rate live in aquatic_stress.* (see aquatic_stress.hpp). proxy_habitat_v1: habitat availability is the static H[i, g] over the six habitat types; the biological stress bits (rain wash, desiccation) live in aquatic_stress.hpp. No-data sentinel for the 2-band state COG. State COG band identifiers. Contract 4.0: both bands are RAW per-cell adult counts (individuals), NOT normalized by any capacity constant (K_MAX retired). In order: band 1 (STATE_BAND_DENSITY) — adults associated with each cell via their patch (post-dispersal) band 2 (STATE_BAND_SUITABILITY) — adults counted at their current position (lon/lat snap)
